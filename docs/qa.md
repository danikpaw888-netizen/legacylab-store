# Проверка LegacyLab перед публикацией

Это план приёмки, а не подтверждение успешных проверок. Отмечайте результат только после реального выполнения на конкретной сборке и URL.

## Автоматические команды

```sh
npm run check
node src/server/sql-check.mjs
```

В отчёте сохраните commit SHA, дату, версию Node, итог каждой команды. SQL-проверки работают в памяти. Они не доказывают успешное выполнение в удалённом D1 — после публикации отдельно пройдите покупку.

## Браузер и доступность

Проверьте 360, 390, 768, 1024 и 1440 px, а также промежуточные ширины. Запишите браузер, устройство/эмуляцию и результаты.

- Нет горизонтального переполнения; длинные названия и крупные суммы не ломают блоки.
- Навигация и покупка доступны без hover.
- Только клавиатурой: меню, поиск, фильтры, варианты, корзина, оформление, кабинет.
- В диалоге фокус удерживается внутри, Escape закрывает, после закрытия фокус возвращается.
- Поля имеют подписи, ошибки связаны с полями; ошибка сети оставляет введённые значения.
- Размеры и количество учитывают остатки.
- Изображения загружаются, у значимых картинок есть alt; нет ошибок JS.
- prefers-reduced-motion уменьшает движение.
- Прямое открытие и перезагрузка /catalog, /product/..., /cart, /account, /orders/... работают.
- Неизвестные маршруты и товары возвращают корректный 404.
- У личных разделов noindex; sitemap не раскрывает аккаунты и заказы.

## Производительность

Измеряйте Lighthouse на опубликованной главной, каталоге и товаре в мобильном режиме. Сохраните URL, дату, профиль сети/CPU, версию браузера и несколько запусков. Не подменяйте измерения оценкой по размеру bundle. Проверяйте LCP, CLS и задержку взаимодействий отдельно.

## Текущий статус

Браузерная приёмка и публичный сквозной тест не отмечены выполненными в этом документе. Результаты должны быть внесены после доступа к браузеру и опубликованному окружению.

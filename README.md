# LegacyLab

**Создавай своё наследие.** Демонстрационный магазин одежды, обуви и аксессуаров с русским интерфейсом, серверным оформлением заказа и имитацией оплаты без банковских карт.

Сайт: [legacylab-store.danikpaw888.workers.dev](https://legacylab-store.danikpaw888.workers.dev). Исходники: [danikpaw888-netizen/legacylab-store](https://github.com/danikpaw888-netizen/legacylab-store).

Этот репозиторий содержит приложение для Cloudflare Workers и D1. Наличие исходников и конфигурации само по себе не означает успешную публикацию: адрес работающего сайта и фактические результаты проверок фиксируются в отчёте развёртывания. Не используйте демонстрационные данные как сведения о реальном продавце, товарах или перевозчике.

## Архитектура

- React + TypeScript: серверный HTML и клиентские взаимодействия, маршрутизация React Router.
- Cloudflare Worker: SSR, JSON API, статические активы, плановая очистка резервов.
- Cloudflare D1: каталог, варианты, пользователи, сессии, адреса, корзины, избранное, промокоды, заказы, платежные сценарии и история статусов.
- Better Auth + Drizzle: регистрация, вход, сессии и восстановление пароля.
- Zod: серверная проверка входных данных.
- esbuild: production-сборка клиента и Worker. Активы включаются в Worker; R2 в этой версии не используется.
- Vitest и тесты SQLite: расчёты, фильтры, остатки, идемпотентность и переходы статусов.

Основные файлы:

## Локальный запуск

Требуется Node.js 24 и npm. Используйте `npm ci`, чтобы установить версии из lockfile.

```sh
npm ci
```

Скопируйте `.env.example` в `.dev.vars` и задайте длинный случайный `BETTER_AUTH_SECRET`. Для локальной среды `BASE_URL=http://localhost:8787`. Файл `.dev.vars` исключён из Git.

Пример в PowerShell:

```powershell
Copy-Item .env.example .dev.vars
```

Сгенерировать случайное значение можно локально командой Node.js; вставьте его в свой `.dev.vars` и не публикуйте в чатах, логах или репозитории:

```sh
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

Создайте локальную базу, примените миграции, заполните каталог и соберите приложение:

```sh
npm run db:local
npm run build
npm run dev
```

Откройте `http://localhost:8787`. Изменения исходников требуют повторного `npm run build`. Локальная база хранится в служебной директории Wrangler, отдельно от удалённой D1. Не добавляйте её в Git.

## Переменные окружения

| Имя | Тип | Назначение |
| --- | --- | --- |
| `DB` | D1 binding | База магазина, задаётся в Wrangler |
| `BASE_URL` | Несекретная строка | Точный origin сайта, включая HTTPS; используется для сессий и CSRF |
| `BETTER_AUTH_SECRET` | Секрет | Секрет Better Auth и HMAC доступа к гостевым заказам |
| `RESEND_API_KEY` | Необязательный секрет | Настоящая отправка писем сброса пароля |
| `MAIL_FROM` | Настройка | Разрешённый отправитель в почтовом сервисе |

Без настроенных `RESEND_API_KEY` и `MAIL_FROM` восстановление пароля возвращает явную ошибку конфигурации. Отправка письма не имитируется. Для включения подключите свой Resend, подтвердите домен отправителя, сохраните ключ в Cloudflare Secrets и укажите разрешённый адрес `MAIL_FROM`. После этого проверьте весь переход по письму на собственном тестовом аккаунте.

Смена `BETTER_AUTH_SECRET` требует отдельного плана: секрет участвует в авторизации и выдаче гостевых ключей. Не меняйте его автоматически при каждом deploy.

## Данные и оформление заказа

Все суммы хранятся в целых копейках. Цена из браузера не определяет итог: сервер загружает актуальные товары, проверяет вариант и остаток, пересчитывает скидку и доставку.

`LEGACY10` даёт 10% от суммы товаров, включая товары с уже сниженной ценой; доставка не дисконтируется. Скидка округляется вниз до целой копейки. Повторный ввод кода не суммирует скидки. В начальных настройках нет минимальной суммы или срока окончания; владелец может их задать. Бесплатная доставка по умолчанию начинается от 15 000 ₽ **после** применения скидки. Стандартная доставка: 490 ₽, 3–7 дней; экспресс: 990 ₽, 1–3 дня. Все сроки и тарифы демонстрационные.

Заказ и позиции записываются одной D1 batch-транзакцией. SQL-триггеры повторно проверяют цену, промокод и остаток, уменьшают доступное количество, запрещают отрицательные остатки и недопустимые статусы. При ошибке пакет откатывается целиком. Уникальный ключ запроса предотвращает создание второго заказа при повторной отправке.

Резерв неоплаченного заказа действует 30 минут. Cron запускает очистку каждые 15 минут; соответствующие API также проверяют истечение резерва. Поэтому фоновое освобождение может произойти при ближайшем запуске после истечения 30 минут. Оплаченные заказы не освобождаются этим механизмом. Отмена освобождает остаток и использование промокода ровно один раз.

Статусы заказа: `awaiting_payment → paid → processing → shipped → delivered`. Отмена возможна до отправки; у покупателя — для ожидающего оплаты заказа, у администратора — также для оплаченного и собираемого. Статус платежа хранится отдельно. При отмене оплаченного демозаказа используется статус `refunded`; реального возврата средств нет, поскольку списания не было.

Для имитации платежа предусмотрены успех, отказ и отмена. Отказ и отмена платежа не создают новый заказ: можно повторить оплату того же заказа до истечения резерва.

Гостевой доступ проверяется по секретному токену в заголовке `X-Order-Token`; одного номера заказа недостаточно. Токен необходимо сохранить в том браузере, где оформлен заказ, либо в предусмотренном интерфейсом безопасном способе доступа. Не публикуйте его. Аккаунт видит только заказы, привязанные к своему ID. Совпадение email не присваивает чужой гостевой заказ.

## Управление магазином

Панель расположена по пути `/admin`. Общедоступного пароля администратора нет. Роль проверяется на сервере для каждого запроса.

### Первое назначение владельца

1. Самостоятельно зарегистрируйтесь на опубликованном сайте с собственным email и паролем.
2. В Cloudflare D1 Console найдите **свою** запись. Проверьте email и скопируйте её ID.
3. Выполните запрос с явными ID и email. Он должен изменить ровно одну выбранную запись.
4. Выйдите из аккаунта, войдите снова и откройте `/admin`.

```sql
SELECT id, email, role FROM user WHERE email = 'YOUR_VERIFIED_EMAIL';
UPDATE user SET role = 'admin'
WHERE id = 'YOUR_EXACT_USER_ID' AND email = 'YOUR_VERIFIED_EMAIL';
SELECT id, email, role FROM user WHERE id = 'YOUR_EXACT_USER_ID';
```

Для снятия прав аналогично установите `role = 'user'`. Не назначайте права автоматически первому посетителю; не доверяйте непроверенному адресу только потому, что он похож на адрес владельца. SQL выполняется через собственный доступ Cloudflare, а пароль остаётся у владельца. Регистрация не включает обязательное подтверждение email, поэтому право владения проверяется человеком, назначающим роль.

### Товары, цены и коллекции

В панели редактируются товар, публикация/черновик/архив, название, URL, артикул, описание, коллекция, категория, состав, уход, посадка, фотографии, варианты и доступные остатки. В API цены задаются в копейках. Не меняйте ID существующего товара или варианта. У архивированного товара сохраняется история; заказ хранит снимок названия, цвета, размера и цены.

Остаток варианта — **доступное**, уже уменьшенное на активные резервы количество. Не подменяйте его полным физическим запасом без учёта резервов. Если удаляете вариант из редактора, сервер сохраняет запись с нулевым остатком для целостности заказов.

Для изображений добавьте файлы в `public/images/`, соберите и опубликуйте приложение, затем укажите пути вида `/images/my-product.webp` в нужном порядке. Первый путь — основное изображение. Для сохранения скорости используйте оптимизированные WebP/AVIF или SVG, ограниченный размер и стабильные пропорции. Прямой загрузки файлов через панель в этой версии нет; R2 не подключён. HTTPS-ссылки допускаются схемой API, но для автономности рекомендуется хранение в проекте.

Коллекция — строковое поле товара; отдельного справочника и редактора страниц коллекций нет. Названия стартовых подборок находятся в `src/shared.ts`. При добавлении новой коллекции проверьте её появление в навигации и фильтрах интерфейса.

### Заказы, промокоды и доставка

Заказы содержат состав, контактные данные, историю статусов и комментарии. Переводите заказ по допустимым шагам; платеж подтверждается через демонстрационный платежный сценарий, а не произвольной сменой статуса на `paid`.

Промокод: код, процент 1–90, активность, минимальная сумма, срок ISO UTC или `null`, лимит применений или `null`. Счётчик учитывает принятые заказы и освобождается при их отмене.

Настройки магазина сохраняются в D1 и перекрывают `defaultConfig` из `src/shared.ts`: название, способы доставки, тарифы, сроки, порог бесплатной доставки, контактный email. Пустой контактный email не следует заменять вымышленным. Общая модель содержит валюту и локаль, но сервер этой версии принимает только RUB / ru-RU: расширение валют требует проверки минимальных денежных единиц и форматирования.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
node src/server/sql-check.mjs
```

`npm run check` последовательно выполняет первые четыре команды. SQLite-проверка запускается отдельно и использует временную базу в памяти, без рабочего D1.

В `.github/workflows/check.yml` подготовлены проверки для push и pull request: Node.js 24, `npm ci`, `npm run check`, затем SQL-тесты. Для их выполнения нужно загрузить репозиторий в GitHub и разрешить Actions. Workflow проверок не имеет секретов Cloudflare и не развёртывает PR в рабочую базу.

Автоматические тесты не заменяют браузерную проверку. Перед релизом выполните сценарии из [docs/qa.md](docs/qa.md), проверьте консоль и размеры 360, 390, 768, 1024, 1440 px. Lighthouse и Core Web Vitals можно указывать только после реального измерения; сборка не доказывает оценку 90+.

## Публикация Cloudflare

Используйте собственный Cloudflare-аккаунт и бесплатный план, если его лимитов достаточно для демонстрационной нагрузки. Проект не включает приобретение домена или платных ресурсов.

Для нового окружения:

```sh
npx wrangler login
npx wrangler d1 create legacylab-store
```

Не создавайте повторную базу, если нужная уже существует. Перенесите возвращённый `database_id` в binding `DB` файла `wrangler.jsonc`; убедитесь, что это целевая база. Задайте точный `BASE_URL` на стандартном адресе Worker или своём домене.

```sh
npx wrangler secret put BETTER_AUTH_SECRET
npm run db:remote
npm run check
node src/server/sql-check.mjs
npm run deploy
```

Команда миграций ведёт журнал применённых миграций. Seed использует `INSERT OR IGNORE` и не сбрасывает текущие цены/остатки. Не заменяйте его массовым удалением таблиц. Перед изменением рабочей схемы делайте экспорт.

При настройке почты:

```sh
npx wrangler secret put RESEND_API_KEY
```

Задайте `MAIL_FROM` в vars и повторно опубликуйте. Секреты не должны находиться в `wrangler.jsonc`, frontend-коде или GitHub.

После публикации проверьте HTTPS, прямое открытие товара и каталога, перезагрузку, вход, гостевой заказ, отклонённый платёж и повторный успешный платёж. Сохраните фактический URL из результата публикации. Не называйте заданный заранее `BASE_URL` доказательством работающего сайта.

### Автоматическое развёртывание и preview

Проверки GitHub Actions включены workflow `check.yml`. Workflow `deploy.yml` запускается после успешных Checks для main и поддерживает ручной запуск. Для активации добавьте `CLOUDFLARE_API_TOKEN` в Settings → Environments → production → Secrets. Нужны права Workers Scripts Edit и D1 Edit только для целевого аккаунта; значение никогда не добавляется в исходники. При отсутствии секрета публикация пропускается с предупреждением. Проверка pull request выполняется без доступа к production-базе. Автоматическое развёртывание требует отдельной привязки GitHub к Workers Builds либо отдельного deploy-workflow с защищённым токеном Cloudflare. Само наличие `wrangler.jsonc` не настраивает эту связь.

Для Workers Builds выберите репозиторий LegacyLab, ветку `main`, установку `npm ci`, команду сборки `npm run check && node src/server/sql-check.mjs` и deploy-команду `npx wrangler deploy`. Секреты приложения задаются на Worker; токен сборок не должен попадать в Git. Миграции перед публикацией следует выполнять отдельным контролируемым шагом.

Preview должен использовать **другую физическую D1**, отдельный `BASE_URL` и отдельный секрет авторизации. До настройки такого окружения запускайте для pull request только проверки. Никогда не публикуйте preview с production binding DB. Официальная схема изоляции: [Cloudflare Preview resources](https://developers.cloudflare.com/workers/previews/resources/).

## Экспорт и резервное копирование

Выполняйте экспорт в закрытую директорию за пределами Git-репозитория: база содержит персональные данные и сессии.

```sh
npx wrangler d1 export DB --remote --output /secure-backups/legacylab-YYYY-MM-DD.sql
```

Для Windows замените путь на свою защищённую папку. Перед важными миграциями и обновлением схемы сохраняйте экспорт и дату/версию приложения. Не прикладывайте дамп к публичным issue.

Проверяйте восстановление в **новой пустой тестовой D1**, не поверх работающей:

```sh
npx wrangler d1 execute TEST_DATABASE_NAME --remote --file /secure-backups/legacylab-YYYY-MM-DD.sql
```

Используйте отдельный конфигурационный файл, указывающий тестовую базу, и проверьте количество записей и целостность. D1 Time Travel доступен в панели в пределах условий текущего тарифа; срок хранения и точку восстановления уточняйте перед использованием. Восстановление рабочей базы может отменить новые изменения, поэтому требует согласованного окна.

## Ограничения демонстрационной версии

- Нет реальных списаний, платёжного шлюза, отправки посылок или интеграции перевозчика. Не вводите настоящие карточные данные.
- 32 товара — концепты. Продуктовые изображения — оригинальные SVG-иллюстрации; это не фотографии реальных изделий.
- Восстановление пароля требует настроенного почтового сервиса. Письма подтверждения заказов не отправляются.
- Файлы изображений добавляются через исходный код, без загрузки в панели и R2.
- Каталог загружается целиком на сервере и фильтруется для демонстрационного объёма. Для большого каталога нужны SQL-фильтрация, индексы и отдельная стратегия кеширования.
- Отдельные справочники категорий/коллекций и многоязычность не реализованы; валюта API ограничена RUB.
- Нет подтверждения email, 2FA, интеграции аналитики, юридического лица и настоящих контактных данных. Публичный магазин нельзя объявлять готовым к реальной торговле только по результатам демонстрации.
- История аккаунта ограничена 100 последними заказами, административная загрузка — 200. Для роста нужна серверная пагинация.
- Гостевой заказ не привязывается к новому аккаунту автоматически по email; сохраните доступ к нему отдельно.
- Реальные результаты браузерной проверки, внешнего deploy, Lighthouse и GitHub CI следует записывать отдельно после выполнения. Непроверенные этапы остаются непроверенными.

## Повторяемые проверки опубликованного интерфейса

`public/qa-check.js` — тестовый сценарий, который сам магазин не загружает. В изолированном браузере можно явно подключить его с `?mode=layout` для геометрии или `?mode=purchase` для гостевой покупки и тестов аккаунта. Режим покупки создаёт только демонстрационный заказ и случайный тестовый аккаунт example.invalid. Итог находится в скрытом элементе `#ll-qa-report`. Не подключайте сценарий к обычным клиентским страницам.

После сборки `node scripts/verify-build.mjs` проверяет production Worker, 11 страниц, HTTP-статусы, статические активы и каталог на временной локальной D1. Фактические результаты публикации фиксируются в `docs/verification.md`.
